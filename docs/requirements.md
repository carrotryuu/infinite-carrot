## 通用约定与技术栈建议

**通用约定**（必须遵守）

- 部署在公司局域网，Docker Compose 一键部署；只有模型 API 和飞书接口需要出网
- 所有业务数据带 `team_id`（组）和预留的 `tenant_id`（对外期多租户），查询一律按组过滤
- 关键操作写操作日志：谁、何时、对什么、改前改后
- 时间以服务器 NTP 时间为准
- 浏览器只需支持 Chrome、Edge

**技术栈建议**（AI 开发建议，仅供参考）

| 层 | 建议 | 原因 |
| --- | --- | --- |
| 前端 | React + TypeScript；状态用 Zustand | 画布生态（React Flow、Yjs）对 React 支持最好 |
| 画布 | React Flow（xyflow，MIT） | 节点连线是主要形态，自带缩略地图、视口裁剪 |
| 画布数据 | Yjs 文档 | 1.0 单人也按 Yjs 存，1.1 开协作不返工 |
| 后端 | Node.js（NestJS）或 Go，二选一按团队熟悉度 | 两人团队，选最熟的 |
| 数据库 | PostgreSQL | 审核说明书已定 |
| 任务队列 | Redis + BullMQ（Node）或 Asynq（Go） | 生成、转码、归档都是长任务 |
| 实时推送 | WebSocket | 生成进度、审核结论实时回到前端 |
| 视频处理 | FFmpeg | 封面帧、HLS 预览流 |
| 图表 | ECharts | 积分和导演看板 |

## P0 模块（内测 1.0）

### M1 账号、组织与权限

**做什么**

- 飞书登录，不开放注册；首次登录自动建账号，由 HRBP 在后台分配组和角色
- 「组 → 项目」两级；一个账号可属于多个组，登录后可切换
- 权限按权限点设计：查看、使用（生成并消耗积分）、测试、上传发布 Skill 和模板、审核与改判、建场、成员管理、账号与积分分配、模型配置。角色是权限点的组合，绑定在组或项目上
- 预置角色：导演、执行导演、美术、动画师（抽卡师）、剪辑、制片、老板、HRBP，各自权限见《项目定义》
- 停用账号、调组；停用后历史记录全部保留

**达成效果**

- 用飞书直接登录，不需要另设密码
- A 组成员看不到 B 组的任何项目、视频和人员
- 同一人在 X 项目是导演、在 Y 项目是动画师，两边权限各自正确
- 剪辑不能修改画布；老板所有页面只读
- 停用的账号无法登录，但其上传、审核记录仍可查

**参考**：飞书开放平台网页应用登录；审核说明书第 2 章

**AI 开发建议**（仅供参考）

- 用飞书网页应用的 OAuth 授权码登录，以 union\_id 作为用户唯一标识，同步姓名和头像
- 表结构：users、teams、projects、memberships（用户、组、项目可空、角色）、roles、permissions、role\_permissions
- 权限校验和 team\_id 过滤放在后端统一中间件里，不要在每个接口里手写
- 权限点用字符串枚举（如 `review.decide`），前端按权限点控制按钮显隐

### M2 NAS 存储

**做什么**

- 服务器挂载 NAS，分区：平台暂存区、待归档、平台备份；项目正式目录平台只读不写
- 画布生成的图片、视频、音频，生成完成后立即下载到暂存区，节点引用平台内部地址
- 每个视频自动生成封面帧和低清预览
- NAS 在线检测：离线时上传、落盘、归档按钮置灰，每分钟自动重连
- 数据库每日备份到 NAS，保留最近 30 份

**达成效果**

- 模型返回的原始链接过期后，画布上的素材仍能正常显示
- 断开 NAS：首页状态灯变红、相关按钮置灰；恢复后自动正常
- 有人直接在 NAS 上删了文件，平台显示「文件已丢失」，不报错

**参考**：审核说明书第 5 章

**AI 开发建议**（仅供参考）

- 建统一的文件表：路径、大小、哈希、来源（生成或上传）、所属组和项目；节点只存文件 ID
- 文件经后端或 Nginx 鉴权后读取，不直接暴露 NAS 路径
- 参考图发给模型时，优先用供应商的文件上传接口或 base64；必须给 URL 时，用带时效的签名链接经出网代理开放

### M3 模型网关与生成任务

**做什么**

- 后端统一接入 LLM、图像、视频 API；新增模型只加适配器，不改业务代码
- 生成全部异步：提交、排队、生成中、成功或失败，结果写回节点
- 失败自动重试（次数可配），也可手动重试
- 刷新或关闭页面后任务继续，回来能看到结果
- 模型配置后台：启用停用模型、默认参数、计费规则（制片权限）

**达成效果**

- 一次提交 20 个视频生成，每个节点都显示排队和进度，页面不卡
- 生成中刷新页面，任务不丢，完成后自动出现在节点上
- 模型临时故障时，节点显示明确的失败原因，可一键重试
- 浏览器里拿不到任何 API 密钥

**参考**：LibTV（整组执行）、TapNow（智能体执行）、updream（Plan 进度可视化）

**AI 开发建议**（仅供参考）

- 适配器统一接口：提交、查询状态、取消、解析结果、计算费用
- 任务表带状态机和幂等键，防止重复提交、重复扣费
- 队列按供应商限制并发；视频类任务用轮询或供应商回调
- 状态变化通过 WebSocket 推给正在看这张画布的用户

### M4 积分记账与看板

**做什么**

- 每次模型调用在网关层记一条消耗流水：人、组、项目、节点、模型、计量单位（次、秒或 token）、积分、成本
- 积分按各模型实际计费规则折算，与供应商账单口径一致
- 制片可给组、项目或个人分配积分；本期只记录和展示，超额拦截放 P2
- 看板：按组、项目、人员、模型、时间段看消耗；老板和 HRBP 全局只读
- 老板视图加导演维度工作数据：待审积压、平均审核时长、24 小时超时次数、通过/备选/退回分布、退回 3 次以上的镜头（数据来自 M10）

**达成效果**

- 月底导出消耗明细，与供应商账单对账差异为 0
- 每笔消耗都能追溯到具体节点和操作人
- 老板能按本周、本月、自定义时间段看每位导演的工作数据，并下钻到镜头

**参考**：updream（每笔积分可溯源）；审核说明书 4.7 老板视图

**AI 开发建议**（仅供参考）

- 流水表只追加不修改，需要修正时写冲正记录
- 看板读按天汇总的聚合表，不要每次扫全量流水
- 失败或被模型拒绝的调用，按供应商是否实际收费来记

### M5 画布基础

**做什么**

- 无限画布：平移、缩放、框选、复制粘贴、打组（Ctrl/Cmd + G）、连线
- 撤销重做、自动保存、缩略地图
- 双击空白处新建节点；本地文件直接拖进画布自动建素材节点
- 快捷键习惯参考 Figma

**达成效果**

- 一集规模的画布（约 100 个视频节点加若干图片、文本节点）打开快、拖动缩放不卡；具体数值由 PoC 定
- 视频节点默认显示封面，悬停或选中才播放
- 撤销覆盖所有画布操作；关闭页面再打开，已完成的操作不丢
- 缩略地图能看到全局并点击跳转

**参考**：tldraw（基础交互）、Miro（缩略地图、大画布导航）、NeoWow、LibTV（双击新建、打组）

**AI 开发建议**（仅供参考）

- React Flow 自定义节点；开启只渲染视口内元素；用自带的 MiniMap 组件
- 缩放到阈值以下时节点改为简化卡片显示，减少渲染量
- `<video>` 元素只在悬停或选中时挂载，其他时候只放封面图
- 画布数据存 Yjs 文档，撤销用 Y.UndoManager
- 所有画布改动走统一的命令层，Agent 和多人协作都复用这一层
- 正式开发前先做 1～2 天 Demo，测 100 个视频节点时的帧率

### M6 节点体系

**做什么**

- 节点类型：文本/剧本、LLM、图像生成、视频生成、素材（图、视频、音频）、资产引用
- 连线表示「作为输入或参考」：上游节点的输出自动成为下游节点的输入
- 生成节点上可选模型、填写提示词和参数
- 节点状态角标：生成中、失败、已送审、通过、备选、退回

**达成效果**

- 动画师把角色资产图连到视频节点，作为参考图生成视频
- 一个图像节点可以同时连到多个视频节点
- 拖入本地视频，自动生成素材节点并上传到 NAS

**参考**：NeoWow、LibTV（5 类基础节点）、ComfyUI（参数面板、执行状态）

**AI 开发建议**（仅供参考）

- 建节点类型注册表：每种类型定义输入端口、输出类型、参数表单、可用模型
- 参数表单用 JSON Schema 描述并自动渲染，新增模型参数不用改前端
- 连线时校验类型是否兼容（比如音频不能连到图像参考口）
- 节点只存参数和文件 ID，不存文件内容

### M7 节点历史与素材对比

**做什么**

- 每个生成节点保留全部生成记录：提示词、参数、模型、结果、操作人、时间、消耗积分
- 节点显示当前版本，可切换到任一历史版本
- 多个结果或版本并排对比：图片网格，视频同步播放

**达成效果**

- 动画师重抽 5 次后，能切回第 2 次的结果
- 2～4 个视频并排同步播放对比

**参考**：Flora（版本历史）、NeoWow

**AI 开发建议**（仅供参考）

- 生成记录表只追加；节点存当前记录 ID
- 并排对比用一个主时钟同时控制多个视频的播放和进度

### M8 资产库

**做什么**

- 项目级共用资产库，分角色、场景、道具等类型
- 资产包含：名称、设定图（可多张，如三视图）、描述、标签、定稿状态
- 从画布节点一键存入资产库；从资产库拖到画布，生成资产引用节点
- 美术和导演维护资产，导演标记定稿

**达成效果**

- 动画师按角色名搜到资产，拖进画布作为参考
- 美术更新角色设定图后，引用它的节点能看到更新提示

**参考**：NeoWow（资产库）、巨日禄（角色库、场景库）

**AI 开发建议**（仅供参考）

- 引用不复制：引用节点存资产 ID 和版本号；资产自身有版本
- 资产表预留作用域字段（项目或公司），P2 做公司级资产库时不用改结构

### M9 Agent 与 Skill

**做什么**

- 画布右侧对话面板；Agent 能读取当前画布（选中节点及其上游）
- Agent 能创建节点、连线、填参数、发起生成
- Skill 管理：上传（Markdown 指令包）、版本、启用停用；制片有上传发布权限
- 对话中用「/」调用指定 Skill，也可由 Agent 自动选用
- 会消耗积分的操作先弹确认卡片（模型、参数、预计积分），确认后才执行

**达成效果**

- 自动流项目导入剧本后，一句话让 Agent 调用拆解 Skill，画布上自动生成人物、场景、道具节点
- Agent 发起生成前一定先确认
- 撤销一次即可回退 Agent 一整轮的改动

**参考**：NeoWow（画布智能体）、updream（Skill 激活、确认卡片）、LibTV（Skill 接口）

**AI 开发建议**（仅供参考）

- 用 LLM 的工具调用能力，工具集：读画布、建节点、连线、改参数、发起生成、搜资产
- Agent 的改动走 M5 的命令层，一轮对话作为一个撤销单元
- Skill 存为 Markdown 加元数据，调用时注入提示词；对话用 SSE 流式输出
- 公司现有的短剧流水线、Seedance 提示词等 Skill 可直接作为首批 Skill 导入

### M10 审核模块

规则以《视频审核平台需求说明书 v1.0》为准，这里只列要点和与画布结合的部分。

**做什么**

- **送审**：画布视频节点点「送审」，选场（只能选导演已建的场）和镜头（选已有或新建，镜号自动分配），系统自动生成版本号 vN；提示词、种子、模型、参考图从节点自动带上
- **外部上传**：网页拖拽上传 MP4/MOV，单文件不超过 500MB，支持断点续传
- **场与镜头**：导演、执行导演建场，场号按创建顺序自动分配；显示名称可改、编号不变；同名提示；可停用
- **转码**：自动转 720p HLS 预览流，原片保留
- **审片界面**：待审队列；播放器支持逐帧、0.25～2 倍速、循环；同镜头多版本 A/B 对比；画批（任意帧圈画加文字，绑定时间码）
- **结论**：通过、备选、退回（退回必填原因，可选标签）；可改判，改判留日志；两人同时提交时先到先得
- **归档**：通过后弹确认框，原片按 `场-镜-vN.mp4` 移到 NAS「待归档/项目名/」；NAS 离线时状态为「已通过·待归档」，恢复后自动补归档；待归档超过 20 个文件时提醒
- **结论回流**：画布节点显示审核状态角标，退回原因和画批可在节点上直接查看
- 回收站保留 7 天；项目结项后只读；关键操作写日志

**达成效果**

- 审核说明书第 9 章的验收清单全部通过
- 从画布送审，导演审完后，动画师在画布节点上直接看到结论和画批
- 从画布送审的版本，生成参数自动带上，不用手填

**参考**：审核说明书 v1.0、Frame.io（播放器和画批交互）

**AI 开发建议**（仅供参考）

- 版本号在数据库事务里加行锁递增
- 预览流用 hls.js 播放；逐帧用 requestVideoFrameCallback，按帧率计算步长
- 画批存为矢量数据（坐标按画面比例归一化）加帧号，用 Canvas 叠加层绘制
- 归档在同一 NAS 卷内移动（rename），不复制；失败进队列重试
- 送审版本关联画布节点的生成记录 ID，结论变化通过 WebSocket 推回画布

### M11 飞书机器人通知

**做什么**

- 每个组或项目可绑定一个飞书群机器人，只推本组本项目的事件
- 推送事件：送审待审、审核结论、24 小时未审催办、资产定稿、阶段推进、生成完成或失败（可配置是否推）
- 每个项目指定一名责任导演；24 小时未审时提醒责任导演，并抄送 HRBP
- 平台内通知（小红点和通知列表）与飞书推送同步

**达成效果**

- A 组的机器人只在 A 组群里推 A 组项目的消息
- 导演 24 小时未审，群里和 HRBP 都收到提醒
- 服务器无法出网时机器人功能自动关闭，其他功能不受影响

**参考**：飞书开放平台（自定义机器人、消息卡片）；审核说明书 4.6

**AI 开发建议**（仅供参考）

- 群推送用飞书自定义机器人 webhook，开启签名校验，内容用消息卡片
- 给个人（如 HRBP）发消息需要飞书应用机器人，可以和登录用的飞书应用共用
- 建统一事件总线，平台内通知和飞书推送订阅同一套事件
- 生成完成这类高频事件建议合并成定时摘要推送，避免刷屏

## P1 模块（内测 1.1）

| 模块 | 做什么 | 达成效果 | 参考 | AI 开发建议（仅供参考） |

## 建议开发顺序（仅供参考）

按模块依赖排序，具体工期由开发评估。

1. **PoC**：画布放 100 个视频节点测性能；接通一个视频模型，跑通「提交 → 排队 → 回填节点」
2. **底座**：M1 账号权限、M2 NAS 存储、M3 模型网关、M4 积分记账（看板可后补）
3. **画布主体**：M5 画布基础、M6 节点体系、M7 节点历史与对比
4. **审核**：M10 审核模块、M11 飞书通知
5. **资产与 Agent**：M8 资产库、M9 Agent 与 Skill、M4 看板
6. **内测**：种子用户试用，制片按各模块「达成效果」逐条验收
7. **1.1**：M12～M15

两人分工建议：一人主攻前端画布（M5～M9 前端），一人主攻后端和审核（M1～M4、M10、M11），第 2 步完成后两条线可并行。
