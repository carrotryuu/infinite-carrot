# T04 组织与权限

## 使用

执行迁移与 pnpm db:seed 后，在 /login 选择演示账号。已分配账号进入 /workspace；新身份仍进入待分配页。顶栏切组仅显示本人所属组，切换记录保存在服务端七天会话中。

- HRBP：进入“账号管理”，选择账号，添加或移除范围配置，按组指定默认角色或按项目指定角色后保存。调组通过删除旧范围并添加新范围完成；启用/停用有确认框。不能修改本人，避免直接移除自己的管理权限。
- 导演：A 组 X 项目使用导演权限，Y 项目单独分配为动画师；X 显示“查看项目成员”，Y 不显示。可切换到 B 组 Z 项目。
- 老板：只有画布查看权限和组织只读人员入口，无账号管理和项目成员管理按钮。
- 剪辑：只有 canvas.view，不能管理成员或修改账号。
- 真实画布、生成和审核业务仍按后续任务推进，当前不提供假操作按钮。

## 数据与查询

新增 teams、projects、memberships、roles、permissions、role_permissions；复用 users、audit_logs。所有表包含 team_id 与可空 tenant_id。目录和身份使用 T03 的组织身份分区；组的 team_id 等于自身 ID，项目/成员通过外键绑定实际组，项目级成员不能关联别组项目。

普通查询通过 TeamScope 注入组范围，接口不接收客户端提供的有效身份或权限。用户本人跨组成员关系仅通过 TeamScope.memberships 的只读范围查找，不能用于读其他模型。HRBP 的账户管理客户端只允许身份/组织模型，拒绝生成、文件等业务模型。所有角色分配、调组、停用、切组写审计；全公司人员和账号后台读取也写审计。

组织级 global.view 与 account.manage 只从组织范围的老板/HRBP 授予，不从某个组的角色提升成全局权限。团队/项目计算移除这两个全局点。项目明确角色覆盖组角色；未单独分配时继承组角色。每次请求重新查询成员关系，撤权不依赖浏览器缓存；当前组被移除后服务端选择剩余所属组，无组则待分配。

## 新接口约定

正式后端使用 organization/policy.ts 的 RequirePermission、Authenticated、Public；全局读还需 GlobalReadable 且必须 GET。全局 AccessGuard 默认拒绝未声明策略的路由。T02 PoC 保留原有启用、来源/令牌与固定权限守卫，显式声明隔离调试入口，不当作正式业务权限。

正式前端用 PermissionsContext 和 usePermission(point, projectId?)，权限来自服务端上下文。PoC 的固定能力判断独立为 usePocPermission，不能用于正式页面。

HRBP 管理写事务先锁定角色目录中的管理行，再复核操作者仍启用且保有组织 HRBP 身份，随后更改目标成员关系/状态与写审计。停用及启用递增 sessionVersion，旧 Cookie 不会恢复。调组保留登录状态，但旧组接口立即返回 404。

## 种子与验收

pnpm db:seed 仅支持 Mock，初始化 A/B 两组、X/Y/Z 三项目、七种演示身份与对应角色。老板、HRBP 的组织权限单独记录；重复执行以审计标记避免恢复被管理员移除的分配。

本机权限测试使用独立 carrot_t04_test 数据库与 Redis DB 4；生产演示仍使用 carrot 和 Redis DB 0。启用 ORGANIZATION_INTEGRATION_TESTS=1、AUTH_INTEGRATION_TESTS=1、GATEWAY_INTEGRATION_TESTS=1 可运行全部集成测试。CI 自动迁移、测试并写入演示种子后执行浏览器测试。HRBP 浏览器测试结束会恢复演示执行导演的原角色与启用状态。

真实飞书仍待接入，首个真实 HRBP 的受控初始化方案待确认；不会根据姓名或客户端传入角色自动提升权限。进入 T06 时提醒补做 T02 真实模型测试，原提醒不变。

## 创建组与项目

HRBP 的账号管理页提供“新组名称 / 创建组”，创建后可为人员分配该组。导演和制片的“我的项目”页提供“新项目名称 / 创建项目”：导演归当前组，制片固定归公司组并自动切换查看新项目。公司组不是全公司公开空间，必须显式分配到具体项目才可见；仅公司组的组成员身份不够。HRBP 可在角色配置中选择公司组、具体项目和角色来分配其他成员。创建者会自动成为其创建项目的成员，所有创建和分配均有审计。
