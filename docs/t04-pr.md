## 问题与结果

此前七个演示账号仅有登录身份。T04 加入组、项目、七种角色及完整权限矩阵：HRBP 可以创建组、分配组/项目角色、调组、停用和启用账号；导演可在当前组创建项目，制片创建的项目固定归公司组，仅显式分配的项目成员可见。导演在 X 项目可查看项目成员，在单独分配为动画师的 Y 项目没有该入口，后端同样拒绝越权请求。顶栏切换组保存在服务端会话中。

所有正式路由采用默认拒绝的访问策略。组范围来自当前会话与数据库成员关系；跨组项目/人员返回 404。老板与 HRBP 只可通过显式 GlobalReadable 人员接口跨组只读，访问写审计；HRBP 的全公司账号管理是 decisions.md 第 5 条的独立例外。

- 独立 PostgreSQL 数据库与 Redis 分区：34 项 Vitest 测试通过，含所有注册路由策略枚举、未标记路由拒绝、跨组 404、项目角色覆盖、组织只读限制、角色调组即时撤权、审计、停用会话失效，以及创建权限和公司组显式成员隔离。
- lint、typecheck、format:check 通过；创建功能部署后，Chrome、Edge 对生产容器的登录/组织专项各 6 项测试通过。
- Playwright 新增导演项目权限/切组保持、老板只读、HRBP 实际调组和双会话停用；最终 Chrome/Edge 容器回归结果见 docs/progress.md。
- Prisma migration 含关联外键、项目与成员组一致性、成员范围唯一约束；种子重复运行不会覆盖已管理过的角色分配。
