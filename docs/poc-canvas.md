# T01 画布性能 PoC

2026-10-27。本报告验证当前实现与当前机器；目标机测试按用户决定移到 T23 使用测试，见 decisions.md 第 8 条。目标机 45 FPS / 3 秒门槛不变。

## 实现与范围

入口 `/poc/canvas`，首页提供链接。100 个视频节点、30 个图片节点、20 个文本节点、150 条直线连线和 MiniMap。五段本地合成 H.264 MP4 样片均为 1280×720、24 FPS、3 秒、无音轨，总素材约 2.83 MB（含封面）。`scripts/generate-poc-media.mjs` 使用 worker 中 FFmpeg 可重新生成。

React Flow 12.12.0 开启视口渲染；节点组件 memo 化，只订阅是否低于 0.4 的缩放阈值，低于阈值只呈现标题。视频默认封面，悬停/选中后向全局池申请名额；整个画布最多挂载 4 个 video，超出请求排队，移出视口或进入简化模式释放名额。图片复用五张样片封面，属于性能夹具而非业务资产。

Yjs 13.6.33 存储节点、边、视口；所有节点变化、视口变化和重置进入 `apps/web/src/canvas/commands/poc-document.ts`。PoC 无持久化、后端接口、模型调用或协作传输，刷新即重置。界面支持空格/中键/右键拖动平移、滚轮缩放、空白处框选、Shift 多选、选中节点组拖动。

## 测量方法

`scripts/measure-canvas.mjs` 仅通过真实鼠标/滚轮/按钮驱动页面，不通过测试专用接口改写节点或视口。平移覆盖多个行列并返回；缩放跨过 0.4 阈值；组拖动在 50% 倍率下真实框选前五行共 50 个节点，验证首尾节点均移动且选择数维持 50。功能 E2E 另验证全部 50 个节点移动相同位移。

首屏：在应用二进制 Yjs update 前开始计时，到节点尺寸初始化、可见封面解码及两次 requestAnimationFrame 后结束。夹具生成不计入此段；这是 **Yjs 加载到首屏**，不是从导航开始的网络加载时间，也不是浏览器合成器的精确呈现时间。计时不含视频解码，因为默认不挂载播放器。

帧率：页面 rAF 连续采样，平均为帧数/实际时长，最低为完整一秒窗口的最低 FPS；同时保存最慢单帧间隔。保留所有卡顿帧，不丢弃异常值。小于三秒或页面切到后台的记录标记无效。该指标反映主线程回调节奏，不等同于 GPU 实际呈现帧数，目标机使用测试还应结合目视卡顿和 Chrome Performance trace。

内存：页面显示 Chromium `performance.memory` 近似 JS 堆，正式数据另外通过 CDP Runtime.getHeapUsage 采样；Windows 浏览器进程工作集为 CDP 返回进程 ID 的 WorkingSet64 之和，可能重复计算共享页，不是独占内存/峰值/完整 GPU 显存。记录在每轮组拖动完成后采集，未主动 GC。

## 结论、限制与后续阈值

当前机器上实现可行，继续采用 React Flow + Yjs。保留视口裁剪、0.4 简化阈值和全局最多四播放器，不因本机余量较大而放宽。测试样片是易复现的合成图案，不能代表真实长视频、高码率素材或 NAS 网络延迟；仅三轮短时采样不能证明无长期内存增长。

按 decisions.md 第 8 条，T01 按功能实现、当前机器实测和工程检查交付；目标机结论为 **尚未测试**，放在 T23 使用测试中验证，不阻塞 T01 当前交付。

T23 需在 16 GB/集显办公电脑的 Chrome 上重跑并归档：平移与缩放平均 ≥45 FPS、Yjs→首屏 ≤3000 ms、视频峰值 ≤4。50 节点拖动平均/最低帧率和内存同步记录，当前没有另行确认其硬性门槛，不擅自添加。若不达标，先用 Performance trace 区分视频解码、节点渲染、Yjs 更新和连线路径成本；再评估真实视频预览码率、布局更新批次或渲染层替代方案，并记录变更前后的同条件结果，不通过缩小夹具掩盖问题。

## 复测

```powershell
pnpm --filter @carrot/web build
pnpm --filter @carrot/web exec vite preview --host 127.0.0.1 --port 4173
# 另开终端；保持测试窗口前台可见
node scripts/measure-canvas.mjs
```

默认 Chrome、可见窗口、三轮、输出 `.local/poc-canvas-results.json` 和 `.local/poc-canvas.png`。可设 `POC_BASE_URL` 指向正式构建地址，`POC_RUNS` 改轮次，`POC_OUTPUT` 指定记录文件，`PLAYWRIGHT_CHANNEL=msedge` 用 Edge。`POC_HEADLESS=1` 仅作自动化排错，不能与可见窗口性能结果混用。

手工使用测试：打开 `/poc/canvas`，点对应“记录”按钮，连续执行操作至少三秒，再点停止，最后导出 JSON。记录机器型号、CPU/GPU、内存、显示刷新率、浏览器版本和视口；T23 再补上真实代表性素材与冷缓存/长时运行场景。

API 依据：[React Flow 性能文档](https://reactflow.dev/learn/advanced-use/performance)、[ReactFlow 属性](https://reactflow.dev/api-reference/react-flow)、[Yjs 文档更新 API](https://docs.yjs.dev/api/document-updates)。
