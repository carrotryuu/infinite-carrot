## 1. 审核说明书
没有单独的审核说明书，审核就是「平台 + 飞书机器人」这一套：
- 送审后，飞书给导演推送待审卡片
- 简单的镜头，导演在卡片上直接点通过、备选、退回（有审核权限的导演、执行导演、制片可点）
- 需要细看的，点卡片按钮跳到平台审片页：逐帧、倍速、A/B 对比、画批
- 结论回流画布，并在飞书私聊通知送审的动画师

需求清单里所有「以审核说明书为准」「审核说明书第 X 章」的地方，改以 requirements.md 的 M10、M11、tasks.md 的 T12～T18 和本文件为准；对应关系：第 2 章 → 本文件第 2 条；第 4.6 节 → M11 与 T16、T17；第 4.7 节 → M4 最后一条；第 5 章 → M2 与 T05；第 9 章验收清单 → M10「达成效果」与 T12～T15 的 E 段。

## 4. 参考视频、音频怎么传给模型（默认做法，待确认）

## 5. 组间隔离与老板、HRBP 的全局查看
- 默认规则不变：所有人只能看到自己所在组的数据。
- global.view 是组织级权限，不绑定在组上，只授予老板和 HRBP。
- 拥有 global.view 时，只能跨组「读」：积分看板、导演看板、审核记录、人员列表。不能跨组写任何东西，也不能打开别组画布编辑。
- 实现：只有标了 @GlobalReadable 的只读接口，TeamScope 才对 global.view 放行；每次跨组读取写 audit_logs。
- HRBP 的账号管理（分组、停用、调组）是独立权限，同样作用于全公司。

## 6. P0「一次提交 20 个视频」和 P1「批量生成」的边界
- P0（T06、T10）：用户在 20 个节点上分别点生成（或 Agent 逐个提交），20 个任务同时排队、各自显示进度，页面不卡。验收的是网关并发能力，不做多选一键生成。
- P1（T26）：多选节点后一键生成，提交前显示总积分预估；后台建一个批次父任务，单个失败不影响其他，可整批取消、整批重试失败项。

## 7. 第二轮评审补充（2026-10-27）
- 任务边界：model_configs、credit_ledger 两张基础表在 T06 建好并由网关写入；T07 只做后台、冲正、汇总和对账。generation_records 表在 T10 建好；T11 只做历史界面
- 依赖：T08 依赖 T05（拖入文件上传），T09 依赖 T07（读模型配置）；按「任务总览」依赖列安排，不只按编号
- 视频格式：平台只有 MP4。外部上传只接受 MP4，MOV 等其他格式直接拒绝；归档命名「场-镜-vN.mp4」，不转码
- 飞书通过：点「通过」后卡片先二次确认，确认后才写结论并归档；与平台确认框走同一个服务方法
- 改判：已归档版本改为备选或退回时，文件若仍在 to-archive 就移回暂存区；已被取走则只改状态并通知制片
- 离线回填：生成结果由 worker 写入 generation_records；画布打开时前端补取未应用的结果；同一节点以最后一次提交为当前版本，较早提交的结果只进历史
- 生成误点：点生成后 3 秒内可取消，不发给模型、不扣积分；3 秒后仍可取消，排队中不计费，已在生成的按供应商规则计费
